# Instructions for book-development contributors

The author requires mandatory capture and handover for every significant session (26 November 2026). Treat conversations as temporary workspaces, not permanent custody. Apply these instructions alongside existing repository governance; do not waive frozen-source, rights, approval or publication requirements.

Read [current state](continuity/CURRENT-STATE.md), [next session](continuity/NEXT-SESSION.md), [active decisions](continuity/ACTIVE-DECISIONS.md), [open questions](continuity/OPEN-QUESTIONS.md), [backlog](continuity/BACKLOG.md) and [knowledge register](knowledge/MASTER-KNOWLEDGE-REGISTER.md). Resolve source authority from actual files and verified revisions. Read relevant chapter and figure notes before editing. Check actual repository state against the recorded snapshot.

Save actual deliverables at their established paths during work. Capture new reasoning, decisions, rejected alternatives, evidence constraints and unresolved questions. Update only affected records, including task tracking and reusable prompts where relevant. Finish with [session-close checklist](continuity/SESSION-COMPLETION-CHECKLIST.md). Verify commit and remote retrieval; distinguish committed from integrated and accepted. Never claim closure if required material is uncaptured. If writes fail, preserve a public-safe portable recovery packet when possible and report exact outstanding destinations; do not fabricate a commit.

Never publish raw private chats, private author details, client material, credentials or restricted feedback. Keep those in approved private custody. No autonomous monitoring or guaranteed automatic execution is implied. Invoke these instructions explicitly in new sessions until integrated and discovered.
