# Capture durable conversation knowledge

After a substantive conversation, extract the decisions, reasons, assumptions, constraints, rejected alternatives, source references, exact deliverables and unresolved questions. Separate an explicit user decision from an assistant recommendation, a frozen source statement, a hypothetical example, a simulated editorial opinion and verified external feedback.

1. Identify the durable content and its intended chapter or topic.
2. Reopen the canonical source for exact defaults, evidence fields or normative claims. Record source path and revision when verified.
3. Retain the original chat privately if available and permitted; do not publish a transcript by default. For public notes use a safe topic/section locator. Mark missing transcript/export as unavailable.
4. Remove private author details, client/employer information, credentials, private links, third-party confidential comments and unlicensed excerpts.
5. Update a chapter note or topical note; add a master index entry only if the insight is new. Preserve rejected alternatives and reasons. Mark supersession without rewriting history.
6. Save actual manuscript, figure or commercial deliverables in their designated location, not only as summaries in the register. A note is not the deliverable itself.
7. Use existing repository integration process; verify actual remote file identity and report any missing/unmerged material. Do not assert completion from a chat response alone.

## Note template

- ID / title / capture date
- Source locator (topic, section, exact revision if available)
- Classification: source-backed / user direction / recommendation / hypothetical / external feedback / unresolved
- Statement and rationale
- Alternatives considered and why rejected or deferred
- Related CH-, D-, FIG-, MF-EVD- identifiers
- Canonical source and constraints
- Intended next use
- Supersedes / superseded by
- Privacy / rights / publication status

Only capture content that materially helps future writing. Routine discussion, repeated scoring and redundant plans need not be retained. Do not represent generated editorial comments as publisher feedback. External feedback should retain date, material reviewed, permitted attribution, exact comment in private custody and public-safe paraphrase only if permitted.

## Mandatory capture rule — author direction 2026-11-26

A response must become a repository asset whenever it creates or materially changes a manuscript, reusable example, diagram, technical rationale, accepted decision, rejected alternative, editorial requirement, commercial draft, genuine feedback, task disposition, handover dependency or reusable prompt. Store complete assets, not only summaries; preserve inline figures as source or explicitly labelled faithful derivatives. For routine clarification with no durable value, no new file is required. Capture at coherent checkpoints, before context exhaustion, and at session close. Keep private originals in approved private storage with safe pointers only. If original material cannot be retrieved, mark missing and do not reconstruct frozen text as exact. If repository writes fail, report exact paths and preserve a portable recovery packet where possible. Follow [continuity instructions](../continuity/README.md) and [session checklist](../continuity/SESSION-COMPLETION-CHECKLIST.md). Do not claim automatic capture when a chat is closed.
